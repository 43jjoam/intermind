# Open questions

These remain OPEN. They are carried forward so they do not disappear during the germination test. This file does not solve them.

## U1 — Domain-specific verification / falsification

Whether domain-specific `FALSIFIED` or `VERIFIED` states are ever justified, for which claim classes, and with what verification process. Not implemented in Stage 0.

## U2 — Resources buying attention

Resource contribution need not buy "truth" in order to buy visibility. Resource contribution must not automatically purchase attention allocation. No ranking system is being designed here.

## U3 — Text / Git and process-competence bias

Git and a text-first Challenge grammar may privilege developers and discursive writers over domain experts who communicate poorly, and may underrepresent visual, embodied, tacit, or other non-discursive knowledge. Stage 0 tests one grammar only.

## U4 — Framework retirement

Corrigibility requires a death condition. Intermind has no right to perpetual existence. The exact retirement threshold remains open.

## U5 — Malicious coordination / reasoning laundering

A well-documented process can still coordinate harm, launder propaganda, or manufacture credibility through staged challenge and revision. Transparent lineage is not harmlessness. No Stage-0 moderation machinery is being built for this.

## U6 — Framework necessity

What specific capability does Intermind require that Git commits, GitHub Issues, pull requests, review comments, RFC processes, or wiki/talk-page history do not already provide adequately? `None yet` is an allowed answer. See [WHY_NOT_EXISTING_TOOLS.md](WHY_NOT_EXISTING_TOOLS.md) once that file exists.

## U7 — Resolution authority

How does an unresolved Challenge become resolved without giving the target author unilateral power, creating a permanent resolver class, relying on majority vote, or pretending disagreement has disappeared? Stage 0 separates address claims from truth verdicts; it does not close U7.

## D1 — Custom software necessity

`P-D1-A`: Markdown/Git span persistence will become unreliable or disproportionately laborious.  
`P-D1-B`: Explicit version IDs, quotations, context, and Git history will be sufficient for the current stage.

Reviewer count does not decide this. A single local success does not settle it. See [PREDICTIONS.md](PREDICTIONS.md) once that file exists.

## D2 — Custody remedy strength

Immediate multi-party custody versus proportional safeguards. Unresolved. Stage 0 uses ordinary single-custodian Git plus logged administrative actions. This is not a verdict for either position.

## C8 — Principle-collision rules

Fixed priority hierarchy versus a contextual collision process. Current scaffold: make the conflict explicit; apply the narrowest rule necessary for non-waivable legal/privacy/safety constraints; preserve as much lineage, corrigibility, and reversibility as possible; log and keep the exception challengeable. What counts as legally non-waivable or "safety" remains contestable (V2-5 residual).

## Terminal-value conflicts

Some disagreement is not missing information. The protocol may document an incommensurable conflict rather than synthesize one answer.

## Affected non-participants

People affected by reasoning or decisions may lack time, literacy, safety, access, technical skill, or desire to participate. Epistemic standing by contribution does not represent them. Not solved in Stage 0.

## Ritual compliance / pseudo-rigor

Protocol-shaped writing may acquire status independently of domain competence. Challenge grammar can be gamed performatively.

## Non-discursive knowledge

Stage 0 tests a text-based grammar only. A successful test must not be generalized into a universal cognition model.

## Material-difference adjudication

Material-difference assertions are challengeable claims, not administrative facts (V2-3 address-claimed for Stage 0). No permanent adjudication mechanism exists.
