# Intermind — Stage-0 germination test

Intermind is being tested as a **public, corrigible reasoning protocol**, not assumed to be an application.

> Can one Problem become sharper through Contribution → Challenge → Revision → persistent unresolved state, such that a later participant can reconstruct what changed and why using ordinary Markdown/Git?

The current experiment explicitly permits this outcome: Intermind may turn out to be only a protocol or convention on existing tools. That is acceptable.

The current rules are provisional. Agreement increases confidence; it does not establish truth. Every rule, including this statement, may be challenged.

## What this repository is not

It is not a web app, social network, search engine, reputation system, token, DAO, treasury, or AI product. Do not treat process fluency (Markdown, Git, Challenge count) as epistemic standing.

## Where to start

1. Read [CURRENT_STATE.md](CURRENT_STATE.md) for the adopted operational freeze.
2. Read [PROTOCOL.md](PROTOCOL.md) for Stage-0 conventions only.
3. Inspect the live seed: [problems/P-SEED-01/STATE.md](problems/P-SEED-01/STATE.md).
4. Unresolved design questions: [OPEN_QUESTIONS.md](OPEN_QUESTIONS.md).
5. Historical reasoning (unchanged imports): [history/review/](history/review/).

A later independent reader should use [LATE_READER_TEST.md](LATE_READER_TEST.md) rather than asking an original participant to narrate the history.

## What a visitor can do

- Read the current Problem, Contribution versions, Challenges, and unresolved remainder.
- Reconstruct lineage from the files and Git history.
- Add a Challenge or Observation under the Stage-0 rules if participating.
- Leave disagreement unresolved rather than forcing convergence.
